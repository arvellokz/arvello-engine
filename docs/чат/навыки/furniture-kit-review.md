# Проверка комплекта чертежей и инструкции сборщику

## Получить файлы
- `git pull -q --rebase origin main` в arvellokz/arvello-engine. Комплекты в репозиторий не кладутся — собрать самому:
  `python3 tools/eng/kit13.py <SKU> out.pdf key=value ...` и `python3 tools/eng/export_parts.py <SKU> out_dir key=value ...`. Комплект с FAIL не выдаётся.
- Инструкции сборщику лежат в `docs/eng-00X/`.

## Просмотреть все страницы дёшево
- `pdftoppm -r 60` (A4) или готовые PNG генератора; склеить по 4 (PIL, 2×2 для A3, 4 в ряд для A4) и читать склейки.
- Нужное место — отдельно `-r 110` + crop.
- Порядок шагов, колонтитулы, количества — через `pypdf` extract_text, не глазами.

## Чек-лист (то, что реально находилось)
1. Рисунок = текст: сторона крепежа (фасад «изнутри» — точки не на лице), стрелки, Л/П.
2. У каждого шага есть рисунок; самые частые места ошибок сборщика (установка ящика на направляющие) — с кругом-увеличением.
3. Безопасный порядок: крепление к стене до направляющих и ящиков (детская мебель); шаг не требует того, что ещё не собрано, и не повторяет уже сделанное.
4. Нумерация шагов сквозная или с префиксами (К/Я/С), ссылки однозначны.
5. Ничто не накрывает крепёж и уголки (столик, надстройки); двойная стойка нарисована двумя панелями.
6. Количества крепежа = спецификации; лишний крепёж обсудить с владельцем (Blum-крепёж не сокращать).
7. Числа пересчитать самому (ось = дно + 38 по Blum; вход самореза в фасад ≥ 6, остаток ≥ 3); при расхождении — просить разложение.
8. Лист «Сборка и контроль» совпадает с инструкцией сборщику по порядку.
9. Колонтитул и штамп — своего изделия; источники Blum указаны одинаково (каталог 2024, страница).
10. Названия позиций не повторяются у разных позиций (собрать «Поз. N <имя>» со всех листов); текст в таблицах не обрезан (и без «…»); вопросы В-… не противоречат листам (припуск, кромка).
11. Что сказано сборщику в A4 (зенковка, число саморезов) — есть на листах цеха A3; все файлы выпуска из одного снимка модели (МАНИФЕСТ).
12. Решения владельца учтены: нет «не согласовано» там, где он решил (значения по умолчанию [М], проверка пробой [О]); ничего не помечено утверждённым.

## Замечания второго проверяющего (ChatGPT/Codex)
- Каждое сверить по коду, тексту PDF и его логам: «подтверждено / частично / не подтверждено» + почему.
- Не воспроизводится — искать разницу окружения (шрифт, ОС, старая копия файла в Obsidian).
- Тесты: проверить код возврата, а не только надпись «все совпали».

## Выход
- Файл `docs/reviews/<задача> — проверка <что> (Claude, чат).md`: «Хорошо», «Исправить» (по важности), «Мелочи». Commit + push.
- Владельцу: 3–7 пунктов простыми словами, главное первым, и готовый короткий текст для сессии Claude Code.
- PDF, которые владелец должен увидеть: SendUserFile + копия в Obsidian.
